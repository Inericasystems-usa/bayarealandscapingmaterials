# Packaging — offline Inerica POS installers

Builds self-contained, **offline**, no-subscription Windows installers of the POS
(a folder + zip). Unzip → double-click the `.bat` → the POS opens. No internet,
no install step, no monthly fee. Data lives in `%LOCALAPPDATA%` so it survives
folder replacement (that's how updates work).

## Build

```bash
# from the repo root, in git-bash:
pnpm install                         # once, so esbuild + deps exist
packaging/build-installer.sh balm    # -> dist/InericaPOS-BALM-offline.zip
packaging/build-installer.sh rs      # -> dist/InericaPOS-RS-TireSales-offline.zip
```

Requirements: `node`, `python` (rs only), and Windows PowerShell (for zipping).

## How it works

One codebase, two store profiles. The build:

1. **API** → bundled to a single `server.mjs` with esbuild (no `node_modules`).
   Runs offline on a local JSON store, auto-seeds on first boot.
2. **Web** → an *isolated npm* build (flat `node_modules`, since pnpm's symlinks
   and Next's `standalone` output both fail to package on Windows).
3. Bundles a portable `node.exe` + the store's launcher `.bat`, then zips.

**Owned edition:** built with `NEXT_PUBLIC_POS_EDITION=owned` → AI features hidden.
Rebuild with `=subscription` to unlock them (the "push an update to move a store
onto subscription" mechanism).

## Store profiles

| | BALM | R&S |
|---|---|---|
| Catalog | landscaping seed (in `apps/api/src/data/seed-products.ts`) | 228 tires, generated by `convert_tires.py` from `../R&STires/data/products.json` (retail + wholesale) |
| Identity | repo default settings | patched by `patch-rs-settings.mjs` |
| Branding | brand artwork | `rs-brand/` (wordmark logo + company.ts) |
| Demo data | seeded (`SEED_DEMO` unset) | skipped (`SEED_DEMO=false` in launcher) |
| Data dir | `%LOCALAPPDATA%\InericaPOS` | `%LOCALAPPDATA%\InericaPOS-RS` |

The `rs` build temporarily swaps 4 committed source files and **always
git-restores them on exit**. Everything else (wholesale pricing, edition gate,
cookie-secure override, `SEED_DEMO` flag) is permanent, BALM-safe code in the repo.

## Shipping an update

1. Land the fix in the repo.
2. Re-run `build-installer.sh <profile>`.
3. Send the shop the new zip. They replace their program folder; their data (in
   `%LOCALAPPDATA%`) is untouched.

## Files

- `build-installer.sh` — the one-command build.
- `convert_tires.py` — R&S tire-catalog → seed converter.
- `patch-rs-settings.mjs` / `stage-web-deps.mjs` — build helpers.
- `rs-brand/` — R&S `company.ts` + `Logo.tsx`.
- `launchers/<profile>/` — the `.bat` launcher + end-user `README.txt`.
- `next.config.mjs` — store-agnostic JS Next config (so `next start` needs no TS at runtime).
